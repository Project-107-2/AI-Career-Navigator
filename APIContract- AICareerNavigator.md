# API Contract — AI Career Navigator

**Base URL:** `http://localhost:4567`

Все запросы и ответы используют формат JSON, если не указано иное.

## 1. Регистрация

`POST /auth/register`

Создаёт нового пользователя.

**Request:**
```json
{
  "name": "Alena",
  "email": "alena@example.com",
  "password": "12345678"
}
```

**Success — `201 Created`:**
```json
{
  "message": "Registration successful"
}
```

**Errors:**
- `400` — некорректные или отсутствующие данные.
- `409` — пользователь с таким email уже существует.

## 2. Авторизация

`POST /auth/login`

Выполняет вход пользователя.

**Request:**
```json
{
  "email": "alena@example.com",
  "password": "12345678"
}
```

**Success — `200 OK`:**
```json
{
  "message": "Login successful"
}
```

**Errors:**
- `400` — некорректные данные.
- `401` — неверный email или пароль.

**Примечание:** после подключения JWT успешный ответ должен дополнительно содержать токен авторизации.

## 3. Получение профиля

`GET /profile`

Возвращает информацию об авторизованном пользователе.

**Headers:**
```http
Authorization: Bearer <token>
```

**Success — `200 OK`:**
```json
{
  "name": "Alena",
  "email": "alena@example.com"
}
```

**Errors:**
- `401` — пользователь не авторизован.

## 4. Получение списка навыков

`GET /skills`

Возвращает список доступных навыков.

**Success — `200 OK`:**
```json
{
  "skills": [
    "Java",
    "Spring",
    "PostgreSQL",
    "Kafka"
  ]
}
```

## 5. Получение списка карьерных ролей

`GET /roles`

Возвращает список доступных профессиональных ролей.

**Success — `200 OK`:**
```json
{
  "roles": [
    {
      "id": 1,
      "name": "Java Developer",
      "description": "Backend developer"
    },
    {
      "id": 2,
      "name": "Frontend Developer",
      "description": "Frontend developer"
    }
  ]
}
```

## 6. Получение информации о карьерной роли

`GET /roles/{id}`

Возвращает информацию о выбранной роли и необходимых для неё навыках.

**Success — `200 OK`:**
```json
{
  "id": 1,
  "name": "Java Developer",
  "description": "Backend developer",
  "skills": [
    {
      "id": 1,
      "name": "Java",
      "requiredLevel": 4
    },
    {
      "id": 2,
      "name": "SQL",
      "requiredLevel": 3
    }
  ]
}
```

**Errors:**
- `404` — роль не найдена.

## 7. Расчёт соответствия пользователя карьерной роли

`GET /roles/{id}/match`

Рассчитывает соответствие навыков авторизованного пользователя требованиям выбранной роли.

Для расчёта используются:
- самооценка пользователя;
- подтверждённые результаты тестирования;
- требуемые уровни навыков для выбранной роли.

**Headers:**
```http
Authorization: Bearer <token>
```

**Success — `200 OK`:**
```json
{
  "roleId": 1,
  "matchPercentage": 71.43,
  "missingSkills": [
    {
      "skillId": 2,
      "skillName": "SQL",
      "currentLevel": 1,
      "requiredLevel": 3
    }
  ]
}
```

**Errors:**
- `401` — пользователь не авторизован.
- `404` — роль не найдена.

## Общие правила

- Формат запросов и ответов: JSON.
- При ошибке возвращается соответствующий HTTP-статус и JSON с полем `message`.
- CORS настроен для разработки.
- Регистрация и авторизация на текущем этапе могут использовать временное хранилище в памяти.
- JWT и проверка авторизации защищённых endpoints планируются на следующем этапе.
- Защищённые endpoints используют заголовок `Authorization: Bearer <token>`.
- Идентификатор пользователя для защищённых операций определяется по токену авторизации.
- Уровни навыков должны быть согласованы между фронтендом и бэкендом.

## Примечания по реализации

- Эндпоинты `/roles`, `/roles/{id}` и `/roles/{id}/match` являются проектируемыми и требуют реализации или проверки в Spark.
- Формат ответа `/skills` сохраняет первоначальный вариант контракта.
- Формат ответа `/auth/login` будет дополнен JWT после реализации авторизации.
- Структура ответов должна быть согласована с фронтендом до интеграции.
